緊急時のとりあえずエラーをスキップする対応
主従データベースサーバーで
sudo systemctl status mysql
従データベースサーバーで
sudo mysql
SHOW REPLICA STATUS\g
エラーnoでググれ、障害が発生すると次から次へとエラーが発生して書ききれない
主データベースで
SHOW BINARY LOG STATUS;
従データベースで
 STOP REPLICA;
CHANGE REPLICATION SOURCE TO SOURCE_LOG_FILE='mysql-bin.0000xx', SOURCE_LOG_POS=xxxx;
START REPLICA;
 SHOW REPLICA STATUS\G
ソースレプリカ両方のデータベースサーバーでデータ不整合がある可能性があるのでチェックしろとAIが言った


以下はソースとレプリカで差をチェックするプログラムと同期するプログラムだ
Percona Toolkitの pt-table-checksum と pt-table-sync の具体的な使い方

ソースデータベースサーバー側
wget https://downloads.percona.com/downloads/percona-toolkit/3.7.1-4/binary/debian/resolute/x86_64/percona-toolkit_3.7.1-4.resolute_amd64.deb
sudo dpkg -i percona-toolkit_3.7.1-4.resolute_amd64.deb

ソースレプリカ両方のデータベースで(認証を甘くするので非推奨)
sudo vi /etc/mysql/mysql.conf.d/mysqld.cnf
mysql_native_password=ON
 sudo systemctl restart mysql

ソースデータベースで
CREATE USER 'pt_tools'@'%' IDENTIFIED BY 'assword123!';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, INDEX, ALTER, SUPER, REPLICATION SLAVE ON *.* TO 'pt_tools'@'%';
GRANT PROCESS ON *.* TO 'pt_tools'@'%';
ALTER USER 'pt_tools'@'%' IDENTIFIED WITH mysql_native_password BY 'Password123!';--認証を甘くするので注意
FLUSH PRIVILEGES;

レプリカデータベースで
ALTER USER 'pt_tools'@'%' IDENTIFIED WITH mysql_native_password BY 'Password123!';--認証を甘くするので注意
FLUSH PRIVILEGES;

ソースデータベースでコマンド
pt-table-sync \
  --user=pt_tools \
  --password='Password123!' \
  --databases=test_db \
  --recursion-method=none \
  --no-check-replica \
  --print \
  h=192.168.1.32 h=192.168.1.129

pt-table-sync \
  --user=pt_tools \
  --password='Password123!' \
  --databases=test_db \
  --recursion-method=none \
  --no-check-replica \
  --execute \
  h=192.168.1.32 h=192.168.1.129
