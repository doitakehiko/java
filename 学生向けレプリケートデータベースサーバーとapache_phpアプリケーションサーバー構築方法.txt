レプリケートデータベースサーバーとapache phpアプリケーションサーバー構築方法
パソコンを3台、出来れば4台用意する
動作確認済のジャンクが狙いめだが、nicは10gや2.5gを刺したほうがいい
以下は実行は必須
メモリテスト
memtest86+
HDDテスト
sudo badblocks -v -s /dev/sda | tee /tmp/badblocks.txt
注:ssdにbadblocksを実行してはいけない
ベンチマークを動かして落ちない程度の安定性は必要
https://zenn.dev/touhoku_japan/articles/e3f19c869f0817
ジャンクの場合以下コマンドを実行してCPU温度の確認もしたほうがいい
watch -n 1 sensors
stress-ng --cpu 0 --timeout 10m
サーマルグリス(CPUグリス)が機能していない場合はCPUに塗り直したほうがいい
新品PCの場合テストとベンチは必要ない
ソフトウェアのヴァージョン最後に記載する

Linuxのインストールやssh接続方法は割愛する
sudo apt update
sudo apt upgrade
は実行済みとする


mysqlのインストール
データベースサーバーとする2台のPCで以下を実行
sudo apt install -y mysql-server
sudo ufw allow from 192.168.1.0/24 to any port 3306
sudo ufw allow from 192.168.1.0/24 to any port 22 proto tcp

主データベースサーバー
sudo vi /etc/mysql/mysql.conf.d/mysqld.cnf 

以下は
テキストエディターでファイルを編集する 
/etc/mysql/mysql.conf.d/mysqld.cnf 
max_allowed_packet      = 64M
max_binlog_size   = 100M
server-id        = 1
log_bin          = /var/log/mysql/mysql-bin.log
binlog_do_db     = test_db


従データベースサーバー
sudo mysql
以下は
mysql> 
で入力する
CREATE DATABASE test_db;

以下は
テキストエディターでファイルを編集する 
sudo vi /etc/mysql/mysql.conf.d/mysqld.cnf 
key_buffer_size         = 16M
max_allowed_packet      = 64M
/etc/mysql/mysql.conf.d/mysqld.cnf 
server-id        = 2
relay_log        = /var/log/mysql/xeon-relay-bin.log

sudo systemctl restart mysql

主データベースサーバー
sudo mysql
以下は
mysql> 
で入力する
CREATE DATABASE test_db;
 GRANT ALL PRIVILEGES ON test_db.* TO 'yourusername'@'192.168.1.アプリケーションサーバーのipadress';

副データベースサーバー
SHOW BINARY LOG STATUS;①

  SOURCE_LOG_FILE='①のFile',

安全なレプリケーションサーバー再起動方法
従データベースサーバーで以下を実行
sudo mysql

以下は
mysql> 
で入力する
SHOW REPLICA STATUS\G
econds_Behind_Source: 0
であると確認する
STOP REPLICA;
sudo systemctl stop mysql
sudo shutdown -h now


主データベースで以下を実行
sudo systemctl stop mysql
sudo reboot

主データベースでmysql起動確認
 sudo systemctl status mysql

Apacheの公開ディレクトリ（ドキュメントルート）の設定変更
/etc/apache2/sites-available/laravel.confテキストエディターで以下のように変更

DocumentRoot /フルパス/multi-db-app/public 
<Directory /フルパス/multi-db-app/public>
    AllowOverride All
    Require all granted
</Directory>


フォルダの所有権変更（www-data への付与）
Laravelプロジェクトの親ディレクトリで
sudo chown -R $USER:www-data multi-db-app
sudo chown -R www-data:www-data multi-db-app/storage
sudo chown -R www-data:www-data multi-db-app/bootstrap/cache

sudo chmod -R 775 multi-db-app/storage
sudo chmod -R 775 multi-db-app/bootstrap/cache

mkdir -p /multi-db-app/storage/framework/views
cat multi-db-app/.env | VIEW_COMPILED_PATH=/multi-db-app/storage/framework/views

sudo chown -R www-data:www-data /multi-db-app/storage/framework/views
sudo chmod -R 775 /multi-db-app/storage/framework/views

phpからmysqlへの書き込み選択テスト
/multi-db-app/routes/api.php
Route::get('/hellodb', function () {
    // 毎回違うメールアドレスにするため、タイムスタンプを付与
    $name = 'inserthello' . time();
    $email = 'inserthello_' . time() . '@example.com';
    $keyword = "inserthello";
    
    // 1. レコードのインサート（自動的に write/主DB へ送られる）
    DB::table('users')->insert([
        'name' => $name,
        'email' => $email,
        'password' => "password123",
        'created_at' => now(),
        'updated_at' => now(),
    ]);

    $results = DB::table('users')
        ->where('name', '=' ,  $keyword )
        ->get();

    return response()->json([
        'keyword_used' => $keyword,
        'results' => $results,
        'message' => 'hellodb insert select test'
    ]);
});

~/multi-db-app$ php artisan route:clear
